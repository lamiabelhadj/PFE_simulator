# C1.1 implementation traceability matrix

## Scope and status

This is a read-only mapping of the implementation behavior frozen at `new-main@27135bf`. The active `sync/v1-canonical` branch contains only the accepted governance documentation commit above that baseline; implementation files are unchanged.

The matrix uses the repository-facing summaries of `02 — Authentication & Behavioral Model` and `03 — Simulator & Dataset Methodology`. It does not create canonical state, event, invariant, anomaly, or field identifiers. Historical names are shown only as implementation evidence.

Status meanings:

- `aligned`: current behavior satisfies the scoped requirement for the capability it claims;
- `partial`: relevant machinery or evidence exists but does not satisfy the complete contract;
- `conflicting`: current behavior contradicts a supplied requirement;
- `absent`: the required capability or record is not implemented;
- `not applicable`: the requirement does not apply to a capability currently claimed.

## Five highest-impact conflicts

1. **Ground truth follows scenario intent rather than observable invariant evaluation.** This affects stealth traces, all historical anomaly types, JSON/context consistency, and ML targets.
2. **Authorization is derived from session reachability.** `SESSION_OPENED` sets authorization success, and wired ABAC decisions do not govern emitted access.
3. **Semantic result and state can disagree.** A transient failure result may still enter the nominal success state.
4. **Replay/history claims lack the required evidence.** Token replay is token age/backdating, source occurrences are not linked, and default generation lacks cross-session history.
5. **No authoritative semantic timeline exists.** Independent session clocks and wall-clock entity logic determine related evidence inconsistently.

## Planning readiness

The repository is ready for **bounded implementation planning**: contracts, baseline evidence, conflicts, missing capabilities, and escalation boundaries are identifiable. It is not ready for an unconstrained Phase 1 implementation plan because semantic event/state mappings, invariant identifiers, several binding/reuse domains, and the monitoring-point observability contract remain unresolved.
